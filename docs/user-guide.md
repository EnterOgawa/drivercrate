# 利用ガイド

DriverCrate 1.0.5はWindows x64向けのアプリです。現在の機器と候補を表示し、利用者が選んだ
driverだけを取得・検査・導入します。実行ファイルは管理者権限を要求します。Windows Update／WSUS、
proxy、証明書、UAC、組織のアプリ実行policyに従ってください。

1.0.5はApp用Setupと更新確認を備えています。将来の正式版を取得して自己更新する実往復と、別管理者アカウントでの更新は未確認です。

## インストールとアプリの更新

正式配布では`DriverCrateSetup-windows-x64.exe`を開き、通常のインストールを行います。
標準配置は`%LOCALAPPDATA%\Programs\DriverCrate`です。現在ユーザー用にプログラムと必要なprofile、文書、スタートメニューを配置し、機械全体への登録は行いません。
インストール先を変える場合も、現在ユーザーのAppData\Local内を選びます。
完了画面の「DriverCrateを起動する」またはスタートメニューから開き、App起動のUACを確認します。
同じ対話セッションで起動できるAppは配置を問わず一つです。更新・解除の前には、別コピーを含む起動中のDriverCrateを通常終了してください。

同版のSetup再実行でプログラムを修復でき、新版は同じ配置へ更新します。古いSetupによる新しいAppの上書きは拒否します。
Windowsのアプリ一覧から通常解除できます。設定・ログ・更新cache・未知ファイルと、別製品のCollector/Collector-dataは保持します。
同梱ファイルの不一致が表示された場合は、同じ正規Setupを再実行してください。実行中ファイルを強制削除しないでください。

Appは起動時と稼働中の24時間ごとに、公式GitHubの新しい正式版を確認します。
「ヘルプ」→「アプリの更新を確認…」で手動確認でき、「更新を自動確認」のチェックで自動確認を切り替えます。
選択は同じ配置の`DriverCrate.settings.ini`へ保存します。確認だけではインストーラーを取得せず、通知の「更新する」で取得・検査へ進みます。
「あとで」を選んだ同じ版は、その起動中の自動確認では再通知しません。手動確認か次の起動で再検討できます。
取得中は「ヘルプ」→「アプリ更新の取得を取り消す」で取り消せます。
検索・ドライバー取得/導入・詳細画面の操作中は通知を待ち、アプリ更新の取得中は新しいドライバー処理を開始しません。

取得したSetupのサイズ・SHA-256・Windows署名・発行元・バージョンを確認し、元の通常ユーザーのExplorerへ渡します。
引継ぎが成功するとAppを正常終了し、通常のSetupを開きます。Setupの取消しを更新完了とは表示しません。
Explorerのない環境や引継ぎ失敗時はAppを維持します。公式ReleaseからSetupを取得し、通常ユーザーとして実行してください。
Appを別の管理者資格で起動しても、更新先は元の通常ユーザーの同じ配置です。別ユーザー領域へ退避してインストールする機能はありません。
App自身の更新はドライバーの索引署名・期限・世代、導入同意・適合性・復旧とは独立しています。
1.0.4には更新機能がないため、最初の1.0.5は手動のSetupが必要です。

## 現在の範囲

通常検索にはWindows Update、Windows Driver Store、公式配布元のProviderがあります。
配布情報だけの候補と、取得・内容検査・端末照合を経て導入可能になった候補は別です。
メーカー名やバージョンが表示されたことだけでは取得・導入できるとは限りません。
通常検索の署名索引の取得前情報は、バージョン・日付・driver発行元を未確認の「—」として表示します。
現在のバージョンcolumnは端末の現在観測です。索引の配布申告や公開日を検証済みINFのバージョン・日付へ読み替えず、
標準INF候補では、取得後に実内容とWindows適合を確認できた場合に、そのINFのバージョン・日付・発行元を表示します。

署名索引からの取得、端末内照合、初回導入、標準INF導入と公式installer引継ぎを共通経路へ接続しています。
取得時には実際のbyte・署名・INFと参照ファイル・このPCへの適合性を検査します。
通常のpayload取得予算は、一file・Provider累計・一検索累計がそれぞれ2GiBです。
Providerごとに最大2file、一検索で最大4fileとし、複数の大容量packageを同時取得できる保証ではありません。
明示した小さい予算は維持し、metadata検索の予算とは別に扱います。
索引の署名やメーカー名だけで導入を許可しません。期限切れの索引は利用できません。

共有package、同意、失効、部分失敗、復旧失敗等は人工試験で確認しています。
配布物の確認範囲は[GitHub Releases](https://github.com/EnterOgawa/drivercrate/releases)を参照してください。

既存の索引storeが所有不明・旧共用形式の場合は処理を停止します。
旧client/setup/dataの互換・自動移行や旧store移動toolは提供しません。
データを無断で削除・resetせず、表示された診断を確認してください。
## 起動前と配布物の確認

重要データをbackupし、Windowsと機器メーカーの復旧手順を確認してください。
Windows 10／11とWindows Serverのx64が設計対象ですが、全version・全機器の実測を完了していません。
正式配布に使う自作EXEはAuthenticode署名と時刻証明を検証します。受け取ったfileごとの署名状態も確認してください。
索引署名は別用途の専用鍵で検証します。通常のソースビルドは証明書不要です。
署名があってもSmartScreen、証明書警告、組織policyの拒否を回避しないでください。

正式な配布物を受け取った場合は同じ配布元のSetupと`.sha256`を比較します。次はファイル名の例で、
現在の公開assetの存在を示しません。

```powershell
Get-FileHash .\DriverCrateSetup-windows-x64.exe -Algorithm SHA256
Get-Content .\DriverCrateSetup-windows-x64.exe.sha256
```

不一致なら実行しないでください。SHA-256は破損・改変検知であり、制作者の認証ではありません。

補助のZIPを使う場合は、同梱ファイルを一緒に展開してEXEを開きます。Appの更新先は上記ユーザー領域内に限ります。
同梱READMEの画像・詳しいガイドは同じ版のGitHubを参照するため、閲覧にはネットワーク接続が必要です。

## 検索と候補

1. `DriverCrate.exe`を起動してUACを確認し、「取得元」で今回使うProviderを確認します。
   設定変更は次の検索から有効になり、表示中の候補や導入先を変更しません。
2. 「更新を検索」を押します。検索は配布情報と候補を表示して止まり、取得準備や件数の確認は表示しません。
   検索開始はEULAや導入への同意ではなく、この操作から公式payloadを検査用取得しません。
   Windowsのハードウェア再検出を一回行い、現在deviceの再列挙後に更新を検索します。
   再検出に失敗した場合は検索を開始せず診断を表示します。同期完了は全deviceの開始やdriver導入完了の保証ではありません。
   再検出中にWindowsが保存済みdriverを自動適用する場合があります。アプリで選んだ候補の導入とは別です。
3. 「種類→デバイス」を矢印で開きます。一つの機器は一行で、デバイス名・現在のバージョン・候補のバージョンの三列で表示します。問題や検査・導入結果は行の詳細で確認できます。
   同じ型番でも別のPnP機器やポートは別行です。複数候補は詳細で比較し、一件を指定できます。
   不明な機器も一覧へ残り、名前・現在のバージョンの欠損だけでは未導入や更新なしと判定しません。
4. Provider別の無効、対象外、候補なし、候補あり、検索失敗、metadata拒否等と、対象・判定・候補件数を
   確認します。候補0件や未判定は「最新」「問題なし」の保証ではありません。

操作buttonの下、最下段の全幅帯には確定した段階、処理済み件数、総件数、全体完了率を表示します。
同期APIから戻るまで進捗が変わらない場合があります。取消しは協調停止で、即時停止の保証はありません。
機器の問題コード28は「未導入」、登録属性取得時は「登録済み」、その他は「現在ドライバー未確認」です。
登録済みも正常動作や最新版を保証しません。

主見出しの「ダブルクリックで候補を表示」の案内どおり、デバイス行でEnterまたはダブルクリックすると、現在構成と候補を比較する5列表を開きます。手動指定がなければ、選択可能で比較できる更新・初回候補のうち最新を初期ハイライトします。明示した候補や処理結果は保持し、主画面の選択は「この候補を選択」で確定します。同内容の重複は一行にまとめ、根拠不足の同じ表示は「別の配布情報」として保持します。セルの文字にポインターを置くと、そのセルの状態に合う短い説明が出ます。詳細は表と「この候補を選択」「閉じる」の2つのボタンで構成し、内部IDや個別診断の全文は表示しません。
閲覧や「閉じる」では選択を変更しません。「この候補を選択」で一候補だけを指定します。
元取得計画に結合した索引の取得前情報も、取得・検査後に適合すれば導入する対象として明示選択できます。
取得前のバージョン・日付・適用性は未確認です。現在構成・失効候補や元取得計画のない表示情報は選択できません。
「推奨・初回候補を表示」では、登録済み機器のバージョン不明な取得前情報や同じバージョンの再導入を更新候補へ数えません。
Windowsが未導入と報告した機器の取得前情報は「初回の確認候補」として残し、取得・適用性が未検査であることと検査済み件数を分けて表示します。
他の取得前情報・同じバージョン・古いバージョンも、表示フィルターを解除すれば詳細から閲覧・明示選択できます。0件は最新や更新不要の確認ではありません。
取得中は最下段に進捗を表示し、検索buttonから同じ取得を取り消せます。取消し後は自動導入しません。
取得・検査結果は表に表示される内容とセルの状態説明で確認します。詳細での指定は取得・導入やEULAへの同意ではありません。
画面の機器情報を公開投稿しないでください。

WUA候補はWUAが現在の端末に適用可能と判定した未導入updateであり、世界で最も新しいOEM版の保証では
ありません。同じdevice・action・空でない明示versionが完全一致する取得元groupも同一内容の保証ではありません。

## 選択と導入

更新・初回候補または未導入の根拠がある取得前確認候補は、通常行から一deviceにつき一計画を選べます。
登録済み・状態不明のバージョン不明な取得前情報や同じバージョン・古いバージョンは、全候補表示の詳細で一候補を明示指定すると選択できます。
複数候補が未指定なら詳細で一件を指定します。
取得前候補のcheckboxは実行対象の選択意図で、検査前の導入許可ではありません。
現在のバージョンは表示専用です。推奨通常更新だけが初期選択の対象で、取得前・初回・同版・過去版を自動選択しません。
「推奨を全選択」「選択を全解除」の後も各対象と取得元を確認してください。

選択後「選択した更新をインストール」を押すと、その選択集合の実行を開始します。
公式取得の規約同意が必要な対象を選ぶと、主画面に規約案内が表示され、buttonが「同意してインストール」になります。
原規約の全文・出典・改訂は「規約全文を読む」から任意に確認できます。全文閲覧や終了、検索・選択だけでは同意しません。
案内した同じ選択・規約への「同意してインストール」で明示同意し、選択した配布物だけを取得・検査します。
別のEULA同意画面は挟みません。同意しない場合はInstallせず、選択を解除してください。
規約の未取得・差替えや選択・検索sessionの不一致では旧案内から実行せず、再確認を案内します。
同じpayloadは共有取得し、署名・hash・INF閉包・Windows適合性を実byteで確認します。
元device・元配布物へ一致する唯一の検証済み候補が全選択に成立した場合に、既存導入へ自動継続します。
取得・検査失敗や曖昧候補、新たな旧版切替では導入を開始せず、理由と検査済み候補を保持します。
曖昧候補は詳細で一件を指定し、旧版は警告を読んで明示選択してください。
検証済みの必要Extension/componentは同じ基本driver計画に含めます。
汎用の取得概要・対象追加・件数確認は挟まず、具体的前提・必要構成・公式installer方式、
Serverのbackup確認と旧版切替だけに必要な判断を求めます。
CNDA等の契約・組織を代表する権限・用途といった具体的な条件は規約同意とは別に確認します。
WUAの未受諾条件は既存の確認を維持しており、WUA候補との混在時はその確認が残る場合があります。
非従量回線で追加の回線確認は表示しません。制限回線・状態不明への無断許可は行わず、取得待ちの理由を残します。

この画面内規約案内と二段階接続のsource実装・内部fake試験は、利用者による新byteの実UI受入・実driver導入とは別です。

clientではlocal暦日の初回に復元保護を準備します。同日後続とアプリ再起動後は、Windows一覧で同じpointの実在を確認して再利用します。
Windowsの24時間抑制で前日等の既存pointが返る場合は、新規作成と区別して表示します。保護未成立ではProviderを呼びません。
実際に開始したnative操作だけは失敗・例外時も同じsequenceへ終了通知します。保存メモの不使用/保存失敗は導入結果と別に案内します。
ServerではSystem Restoreを呼びません。DriverCrateがbackupを作らないこと、
事前のsystem state／bare metal backupまたはhypervisor checkpointと復旧手順の確認を専用dialogに示し、
既定「いいえ」から管理者が明示同意した場合だけ進みます。

WUAはWUAの取得・導入を使います。Driver Storeと標準INFは直前に同じdevice、package、署名、依存閉包、
Windows選択条件を再確認し指定導入へ渡します。旧版切替には追加警告があります。
開発sourceの標準INF経路では、driverが必要とする付属fileも元packageの一部として検査します。
別device向けINFの取込みだけで、そのdeviceも同時導入することはありません。
DriverCrateは付属EXEやscriptを個別に起動せず、Windows標準のdriver導入へ渡します。
Windowsが元driver宣言を処理する際のvendor helper内部動作を、全て確認したという意味ではありません。
このsource変更の内部確認と、現在の配布EXE・実driver導入の受入は別です。
Driver Storeにあることも切替後の正常動作の保証ではありません。
公式installer方式は検証済みEXE／MSIの対話画面へ引き継ぎます。scan中に起動しません。
表示された選択driverの範囲を守り、追加appやfirmwareへ同意しないでください。
終了codeだけではdriver導入済みと確認できず、標準INFの内容合格やWindows rankとは別です。

## 結果と復旧

取得、導入API結果、実状態、再起動要否を別に確認します。一覧は短い結果を示し、
一部失敗・HRESULT・必要構成の個別結果は同deviceの詳細で元候補ごとに確認できます。
検証の結合を確認できない候補でも、同じ画面が保持する個別実行結果は過去の履歴として表示します。
履歴は現在の検証結果や導入許可ではなく、新しい検索で破棄されます。
必要Extensionの個別反映が確認できなければ「適用未確認（Windows管理・個別反映は未確認）」を残します。
完了後も元の表示filterとtreeを保持し、選択deviceの読取り専用事後確認と結果を残します。
全Providerの自動検索は行いません。
読めた名前・現在のバージョン・種類・Windows問題状態を同じ機器の行へ自動反映します。確認できなければ実状態未確認と表示します。
適用・変更なし・再起動待ち・実状態未確認を分け、現在のバージョンを推測で書き換えません。
導入完了時は全体を検索し直さず、成功した対象だけチェックを外します。未処理の候補・チェックと
開閉・スクロールを保持し、同じ一覧から次の候補を普通に選択できます。次の明示Installで対象の現在状態、
適用性・署名・元期限・規約と復旧を再検証します。有効な取得済み本体は再検査して使い、別deviceの検査や
承認を流用しません。再起動待ち・引継ぎ・状態不明は作用対象を保留し、個別結果を残します。
元選択への実一致と既知更新の解消を確認できた対象は選択枠も消し、次に「推奨・初回候補を表示」を明示適用すると除外します。
全表示では結果を閲覧できます。API成功だけ、旧版選択、再起動待ち、必要構成未完了、既知のより新しい推奨候補が残る対象は解消扱いにしません。
ここでの解消は元検索で既知の更新についての確認で、全配布元の最新保証ではありません。

問題時はDevice Manager、Windows Recovery Environment、メーカーの復旧手順を使用します。
clientの復元ポイントは完全backupではなく、Serverは事前に用意したbackup／checkpointを使います。
DriverCrateは復旧成功を保証しません。共有する診断にはversion、操作段階、一般化したHRESULTを使い、
機器ID、serial、title、URL、local pathを含めないでください。

保護境界は[セキュリティ設計](security.md)を参照してください。
