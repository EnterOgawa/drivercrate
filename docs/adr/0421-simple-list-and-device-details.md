# ADR 0421: 三列一覧とデバイス詳細への集約

- 日付: 2026-10-28
- 状態: 採用。検索後の自動確認はADR0422で置換。三列/詳細の実装・内部試験はG13-I7r270b/c、実UI受入は271d。

## 背景

利用者は状態列と上部の「情報検索」「取得準備」および説明帯を通常画面から外し、
デバイス名・現在版・候補版とcheckbox選択へ絞ること、詳しい情報は行のダブルクリックで
表示すること、操作メッセージを最下段へ置くことを指示した。

## 決定

主一覧は種類→デバイスの二階層、一device一行、三列とする。状態列の見出し・幅・描画・
ソートを除き、問題コード・取得検査・適用性・取得元・個別導入結果は既存詳細dialogへ保持する。
不明機器・未取得・導入後もEnterまたはダブルクリックで開け、閲覧だけでは候補指定やcheckを変えない。
分類行の展開・折畳みは標準TreeViewへ残す。

上部二buttonと説明controlは生成しない。ADR0422に従い通常「更新を検索」は候補表示で止まり、
選択してInstall操作を行った対象だけを必要規約・取得検査・既存導入へ続ける。
取得中は同じ主操作を取消しへ切り替え、終端まで待つ。内部backendと内部fixture用commandは維持する。

比較・選択・導入操作帯の下に、既存の全幅決定型progress/message帯を置く。
取得後の長い技術reportは自動dialogで割り込まず、デバイス詳細内の閲覧専用entryから確認できる。
これは全体reportであり、そのdeviceの全検査成功を意味しないと明示する。
明示選択・必要なEULA・復旧と旧版/方式等の新条件への判断は維持し、汎用の件数確認は重ねない。

## 境界と検証

状態機械・候補identity・取得/署名/INF/適用性・同意・導入後のread-only観測は変更しない。
fake/UIで三列、control不在、最下段配置・resize/DPI、詳細閲覧と選択保持、不明機器・導入後結果、
通常検索→checkbox→Install→必要規約→取得検査→導入、および取消し/失敗を確認する。
実App操作・実導入・通常output置換・署名・Task・公開は本工程に含めない。
