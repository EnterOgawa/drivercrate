# ADR 0607 署名付き索引と個別候補の期限を分離する

- 日付 2026-11-28
- 状態 1.0.14の公開候補に実装。新旧入口の実配信と署名済み配布物の照合を公開前に確認する。

## 全体と個別の期限

署名済み索引の有効期限は発行後14日と最長の元記録の期限で上限を定める。有効な索引のうち、元記録の期限内にある候補を照合する。
個別の利用期限はマニフェスト、所属する領域、元記録のうち最も早い期限とする。
照合開始・完了、候補の表示・準備、通信前後、最終導入で期限を確認する。期限切れの候補を再掲載するには公式配布を再確認する。
署名・原内容のハッシュ、配布元、端末への適用性、利用者の同意と復旧の検証を継続する。

## 旧版からの移行

1.0.13までのクライアントは、従来の署名マニフェストを `index/current.json` から読み、本文に期限切れの既知候補がある場合は索引を拒否する。
従来の入口では全候補が期限内にある投影を使う。1.0.14は、個別期限に対応した署名スキーマ `driver-index-manifest-v2` を
同じ `driver-index` ブランチの `index/current-v2.json` から読み、元の圧縮本文を照合する。新版の `legacyManifestSha256` は、同世代の旧マニフェストの署名対象を照合するための値とする。

新旧の入口は、同じ配布元・署名鍵・世代を使用する。固定アセットを読み戻した後、両入口を同じ公開更新で切り替える。
新版を配布する前に、同じ世代を両入口から匿名で取得し、旧版と新版でそれぞれ検証する。新入口の異常時は従来の入口へ切り替えず、検証の結果を表示する。
保護済みキャッシュの原署名と世代を検証し、新版の受理後は旧版への巻き戻しを拒否する。

## 内部検証

期限切れと期限内の候補の混在、期限の境界時刻、索引全体の失効、同じキャッシュの再利用、世代の衝突、取得中の個別失効を回帰試験で確認する。
