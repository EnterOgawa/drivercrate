# ADR 0416: デバイスごとに一行の通常一覧と詳細内の候補選択

- 日付: 2026-10-27
- 状態: 採用（source実装・内部試験と通常アプリ受入・署名配布物は別に記録する）
- 関連: ADR 0149、0150、0413、0414、G13-I7r263

利用者は「ツリーの表示としてはできる限りシンプルにデバイスマネージャーのようにしてほしい、
一つのドライバーに複数表示されていると混乱する」と指示した。現在構成・検査済候補・取得前の
索引情報を同じdeviceの子行へ並べる三階層表示を更新する。AGENTS第5節の従来の子行要件より
この指示を優先する。

## 決定

1. 主一覧はWindows種類カテゴリ→PnP deviceの二階層とし、opaque device identityごとに一行にする。
   同じ名称・型番・共有packageでも別PnP device/functionを統合しない。現在のOS属性を名前・分類・
   現在版の表示元とし、名前欠損は生IDで補わず「名前を確認できないデバイス」と表示する。
2. 列はデバイス・現在版・候補版・状態の四つとする。現在観測、取得前metadata、更新・同版・過去版、
   Provider/取得元、日付・署名・内容・適用性・方式・必要構成・個別診断はdevice詳細へまとめる。
   検査済候補があれば取得前metadataより優先して要約し、metadataの申告を検証済みINF版へ転記しない。
3. 詳細は標準の候補選択欄と読取り専用本文を持つ。選択欄の閲覧だけでは導入候補を変更せず、
   「この候補を選択」の明示操作で同deviceのinstall可能な一候補を指定する。複数候補を
   device checkbox一つからまとめて選ばない。未指定の複数候補は詳細を案内し、一候補のdeviceは
   checkboxでその候補だけを選択できる。現在構成・取得前・失効候補は導入選択不可とする。
4. 候補vectorとopaque candidate/session/device/package identityは保持し、名前・版・URLからIDを
   推測しない。推奨全選択は既存の検証済み優先規則で一device一候補、全解除・filter・keyboardは
   同じ保持selectionを使う。索引初回・同版・旧版は既定未選択を維持する。
5. 導入後は全候補を失効し、個別実行結果を候補identityで保持する。device行は当該deviceの結果を
   要約し、詳細では元候補ごとの取得/導入/必要構成結果を閲覧できる。現在版を導入結果から補完しない。
   再選択は新scanを要し、EULA・復旧・worker/native検証・Provider動作は変更しない。

## 検証と範囲

非通信の本物MainWindow/TreeView/dialog/worker fixtureで二階層・一device一行、同名別device、
複数候補の明示指定・一device一計画、metadataのみの非選択、取得後の候補優先、推奨/解除/filter、
未導入と観測不能、stale拒否・部分結果・失効後の結果保持を確認する。変更品質gateとx64
Debug/Releaseの必要build/unit/UIを実行する。既存利用者アプリは操作せず、実通信・実導入・
署名/output差替・公開はこのsource実装工程に含めない。
