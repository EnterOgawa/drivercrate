# ADR 0424: 更新候補と未導入機器の取得前確認を区別する

- 日付: 2026-11-02
- 状態: 採用。実装はG13-I7r273b、内部検証は273c、主担当と利用者確認は273v/d。
- 関連: ADR 0150、0416、0421、0422、0423

## 原因と決定

元取得targetへの結合は選択意図の根拠であり、更新や初回導入の判定ではない。
従来の推奨filterはこの結合だけで未取得参照を通し、同じ条件で推奨件数へ数えていた。
署名索引の取得前参照はdriver versionを持たず、現在版と同版かは未確認である。
recordの配布versionをINF driverVersionの代用にせず、空の現在版も未導入の根拠にしない。
利用者画像の版表示だけでは実OSの導入成功・Code28解消・再起動要否は確定しない。

通常filterでは、既存Providerの推奨通常更新と検証済み初回、および同じ署名索引から
取得・端末検証後にUPDATEと分類された候補を表示する。同版REINSTALL・旧版・版不明の
取得前参照は更新候補へ数えず、全候補表示と詳細の閲覧・明示選択を保持する。
表示filter、checkboxの代表候補、詳細から選択できる対象、下部件数を同じ分類へ結合する。
適用性は既存Provider・Windows・実byte検査を正本とし、この表示分類は導入権限を発行しない。

例外として、同scan・同deviceへ結合した妥当な現在観測がNOT_INSTALLEDを示す場合、
有効な元取得計画に結合した参照を「初回の確認候補」として通常filterへ残す。
既存観測契約のCode28優先を維持し、古いdriver keyや版文字列だけでこの明示観測を隠さない。
取得・適用性は未検査と表示し、検査済みの更新・初回候補数と分離する。REGISTERED、UNKNOWN、
観測不正・旧session・別device、現在版欠損だけの参照をこの例外へ含めない。
これにより、未導入機器の検索→選択してInstallという通常二段階の入口を維持する。

不明参照をfilterから除いて0件になっても「最新」「更新不要」とは案内しない。
未取得情報と全候補を表示する方法を最下段へ示し、未知を成功へ換算しない。
同名の別device/functionはopaque identityで分離する。索引形式・collector・永続cacheや
メーカー別分岐を追加せず、272の規約snapshot・任意全文・明示Installと既存安全境界を維持する。

## 固定する内部検証と戻し方

既存fake UIで、画像相当の登録済み二機能（現在版1.9.74.0・取得前参照版空）の誤表示を
修正前に再現する。版不明・登録あり現在版欠損・観測不正/旧session/別device、Code28初回、
検証済み同版・旧版・新版、正当なWUA/Store候補、同名別device、複数候補、filter ON/OFF、
件数と代表候補、全候補での明示選択と閲覧を固定して確認する。元two-initial fixtureはfilterを
解除せず選択→規約案内→Installを維持する。272の12条件を回帰させる。
実App・通信・実再検出・実復旧・実導入は行わない。戻す場合はUI分類と文言を戻し、
Providerの候補・私有導入許可・元取得計画・索引署名やbyte検証を変更しない。
